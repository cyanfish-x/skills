# 周报撰写指南

本指南是通用方法论，不绑定特定项目。切换工作区后同样适用。

## 模块名 → 中文业务名的通用推断

脚本输出的 `key` 是从文件路径自动提取的目录名（可能是英文/拼音/缩写）。撰写周报时按以下方法转成可读的中文名：

1. **优先用 commit message 的线索**：提交说明里往往直接出现中文业务词（如"分标控制""编制概算""投资计划"），直接采用，比生翻目录名更准确。
2. **目录名是英文/拼音时合理翻译**：
   - 全词：`user`→用户，`order`→订单，`payment`→支付，`auth`→权限/认证，`material`→物资，`cost`→造价，`report`→报表，`dashboard`→看板，`setting`→设置，`profile`→个人中心，`inventory`→库存，`schedule`→排程。
   - 缩写：`usr`→用户，`prod`→产品，`mgr`/`mgmt`→管理，`cfg`/`conf`→配置，`auth`→认证，`sys`→系统，`emp`→员工，`hr`→人事，`fin`→财务，`adm`→管理后台。
   - 拼音：按常见业务词还原（如 `zaojia`→造价，`wuzi`→物资），不确定时保留原 key。
3. **拿不准就保留原 key**：不要杜撰功能。宁可写"模块 xxx"也不要瞎编业务名。

## 分组类型的用法（归类参考，不直接成节）

- `kind=module`（业务模块）：模块名转成中文业务词后写进条目，用「」标注功能点。
- `kind=common`（公共/基础）：api、组件、工具、配置、构建等通用改动，合并成"公共组件/基础优化"类条目。
- `kind=other`（无法归类）：能并入就近条目就并入，通常省略。

## 撰写要点

1. **分项目汇报**：每个活跃仓库一节，标题 `【<项目中文名>】`。项目中文名优先取仓库路径中的中文目录名（去掉数字前缀，如 `22_两河口机电` → `两河口机电`），没有中文目录则取仓库名；拿不准保留原名，不要杜撰。
2. **编号条目**：项目内从（1）开始连续编号，每个功能模块/主题一条；单项目 3~6 条为宜。
3. **动宾短句**：以"完成/修复/优化/重构"等动词开头；模块或功能名用「」标注；一条内的并列子项用"、"连接、以"及"收尾；行末用分号，最后一条用句号。
4. **合并润色**：同一功能多次提交合并为一条，去重（多次微调同一功能只写一条）。不照搬 commit message 列表。
5. **过滤噪音**：纯 Merge 提交已过滤；无关的格式/调试提交可合并或省略。
6. **客观陈述**：只描述已完成的工作；不确定的不要写。

## 周报模板

模板（多项目时依序并列，每个项目编号重新从（1）开始）：

```text
【<项目中文名>】
（1）完成「<功能名>」<改造/开发内容及并列子项>；
（2）完成 <功能> <问题>修复 及 <优化项>；
（3）完成 <公共组件/基础能力> <重构内容> 及 <优化项>。
```

真实示例（2026-08-10 ~ 08-16，两河口机电项目）：

```text
【两河口机电项目】
（1）完成「QBS 节点选择弹窗」虚拟滚动改造；
（2）完成 QBS 弹窗重置/搜索卡死修复及多选折叠优化；
（3）完成三维查看器 重置操作按钮 及 快照差分重套工具 开发；
（4）完成三维查看器 重置/隐藏/历史/虚化等功能重构 及 模块边界优化。
```

日期、姓名、下周计划默认不输出；用户明确要求时再补。

## 输出格式（重要）

周报正文必须**整体放进代码块**呈现给用户，且每条独立成行、条目间不空行：

- **原因**：Markdown（GFM/CommonMark）会把段落内的单个换行（软换行）渲染成一个空格，连续行会被合并成一段；空行分隔又过于稀疏。代码块原样保留换行，且方便用户直接复制。
- 代码块之外的补充说明（如模块名待确认）正常用 Markdown 书写即可。

## 切换工作区注意事项

- 脚本默认用**当前工作目录**作为仓库，自动读取该仓库的 git 账户，无需任何项目特定配置。
- 模块提取采用**通用启发式**，自动适配 monorepo（packages/apps/services）、前端（src/pages、views、modules）、Next.js（src/app）、通用 `src/<m>/` 等结构。
- 启发式不做"顶层目录"兜底，以免把 Java 包前缀（com/、org/）等误判为模块。纯顶层划分的项目（无 src/、无 monorepo 边界）请用 `--module-regex` 显式指定。
- 如果某项目结构特殊导致启发式不准，运行脚本时传 `--module-regex '<正则>'` 覆盖（正则需含 1 个捕获组），例：`--module-regex 'com/\w+/(\w+)/'`。
- 同一人多邮箱：用 `--author <姓名> --author-by name` 按姓名匹配。

## 多人/多账户提示

- 默认只汇总本机 git 账户的提交。如需汇总他人，加 `--author <name或email>`。
- `git log --author` 是子串正则匹配，传入的值会作为正则。
