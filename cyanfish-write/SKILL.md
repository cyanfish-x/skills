# 青花鱼博客写作风格指南

本 skill 基于博客 `source/_posts/` 下既有文章总结,用于保持青花鱼一贯的写作调性。**写或改任何一篇新文章前,通读本指南;写完后用文末检查清单自检。** 项目专属的工程流程(如何创建文章、abbrlink 生成、部署)见项目的 `AGENTS.md`,本 skill 只管写作。

## 1. 作者人设(写之前先认领这个声音)

- 一个长期跟 **Cesium / WebGIS / 前端 / 运维** 打交道的 Giser,自称"青花鱼",图片域名 `picture.cyanfish.site`。
- 性格:**实在、爱折腾、能白嫖绝不付费、踩过很多坑愿意分享、爱用比喻把复杂概念讲明白**。
- 第一人称常用"我",拉近读者用"我们"或"你"。
- 经常提到"问了下 GPT / 拷问了 deepseek 豆包",把 AI 当同事吐槽或求助,这是固定的口癖之一。
- 不要端着、不要学术腔、不要纯工具书口吻。**像一个老哥在工位上边操作边跟你讲。**

## 2. 标题风格

**主标题(frontmatter 的 title):追求情绪化钩子 + 数字承诺,文件名反过来用平实描述。**

| 套路 | 例子(均出自既有文章) |
|---|---|
| 情绪化感叹 | 宝塔面板真香警告!Vue+SpringBoot项目部署全流程详细指南,30分钟搞定上线 |
| 反问/挑逗 | 别再傻傻分不清!5分钟搞懂像素、分辨率、PPI、码率 |
| 白嫖/省钱 | 告别 Copilot 付费!谷歌 Gemini CLI 每天白嫖 1000 次请求,保姆级教程来了 |
| 主标题 + 副标题(破折号/冒号) | 从 0 到 1 手写 WebGL:原来 3D 渲染的底层逻辑,就是拍照片 |
| "手把手"/"保姆级"/"全流程" | 使用宝塔部署前后端项目全流程、AIAgent工具优雅使用教程 |

**文件名(`source/_posts/NN-xxx.md`)**:编号 + 平实主题词,如 `48-使用宝塔部署前后端项目全流程.md`、`46-bug-记录前端项目中依赖冲突bug的解决过程.md`。

**数字承诺常用词**:5分钟、10分钟、30分钟、每天1000次、零基础、从0到1。

## 4. 必须有的语言特征

### 4.1 类比和比喻(青花鱼最大的辨识度)

复杂概念必须配一个生活化类比。既有文章里的经典:

- **WebGL** = 光栅化引擎,像画家作画,代码是大脑,WebGL 只是画笔。
- **MVP 矩阵** = 摄影师拍照:摆 Pose(模型变换)→ 找机位(视图变换)→ 选镜头按快门(投影变换)。
- **像素** = 拼图的马赛克小方块。
- **SPA 状态** = 不刷新页面时应用在内存里维护的所有数据。

**写作时自检:这一段如果只有定义和公式,必须补一个比喻。**

### 4.2 emoji(教程/科普类必带,bug/实战类可选)

- 二级标题前常用:`💡 🛠️ 🚀 💣 🔍 ⚡ 🎯 📌 ⚠️ ✅ ❌`
- 教程类前缀示例:`💡 背景与痛点` / `🛠️ 先决条件` / `🚀 实战步骤` / `💣 避坑指南`
- 概念科普的小标题常用 `🔍 什么是 XXX?`
- 用 `❌` / `✅` 在代码注释里对比错误做法 vs 正确做法。

### 4.3 口头禅(适度散落,不要堆)

> 说白了、好家伙、本着"..."原则、于是、这是后话、撸起袖子开干、量不大管饱、牛逼、真香、踩坑、血泪经验。

**频率上限(硬规则):** 同一个口头禅一篇文章**最多出现 2 次**,通常 1 次就够。写完后 grep 统计,超了就要删到 2 次以内。情绪强烈的口头禅(好家伙、真香、牛逼)尤其容易堆,注意间隔使用,别连续几段都是同一个。

### 4.4 强调与引用

- **加粗**关键词、数字、结论句。一个段落至少有一处加粗,但不要整段加粗。
- 用 `>` 引用块承载:官方原文、重要警告、AI 的回答、易错提示。
- 数字、参数、文件名、命令用行内 `code`。
- **标点一律用中文全角**:逗号 `，`、句号 `。`、冒号 `：`、问号 `？`、感叹号 `！`、分号 `；`、括号 `（）`。正文里禁止出现英文半角标点(代码块、命令、URL、Markdown 链接/图片语法、frontmatter 里的 date 除外)。写完 grep 检查:`grep -nE "[,?!:;()]" 文章.md` 只剩 frontmatter/代码块/链接里的命中。

### 4.5 配图

- 操作步骤几乎每步一张截图,图床域名固定 `https://picture.cyanfish.site/xxx.png`。
- 写新文章时**留好图位**(用 `![描述](图片占位)` 或注释提示作者补图),不要凭空编造 URL。
- bug 类至少一张报错截图 + 一张排查过程截图(AI 对话截图是常见素材)。

## 5. frontmatter 格式(严格遵守)

```yaml
---
title: 这里是带情绪钩子的主标题
date: YYYY-M-D HH:MM:SS
updated: YYYY-M-D HH:MM:SS
cover: 'https://picture.cyanfish.site/xxx.png'
categories:
  - 教程        # 或:技术 / 记录 / bug记录
tags:
  - 标签1
  - 标签2
abbrlink: 8位十六进制短链   # 见下方要点
---
```

要点:
- `title` 必须是情绪化主标题,不要直接用文件名。
- `date` / `updated` 用 `YYYY-M-D HH:MM:SS` 格式(M/D 不补零,如 `2026-1-10 23:23:35`)。
- `cover` 留给作者填,不要瞎编;可写占位注释提醒。
- `categories` 通常 1 个,`tags` 2~4 个。
- `abbrlink`:frontmatter 里**必须存在且非空**(唯一短链)。它的生成方式、查重、文件创建命令属于项目工程流程,按 `AGENTS.md` 执行,本 skill 不重复。
- 文件名:`NN-标题.md`(编号 + 平实主题词,编号规则见 `AGENTS.md`)。

## 6. 代码块规范

- 必带语言标识:```typescript / ```js / ```bash / ```json / ```yaml。
- 关键行**用中文注释**,不要英文注释。例如:`// 让相机"盯着"某个目标看`。
- 对比错误/正确做法时用 `// ❌ 错误方式` 和 `// ✅ 正确方式`。
- 报错命令、伪代码也贴,真实优先,但要补中文注释帮助理解。
- 长代码分段贴,每段之间用一句中文过渡,不要一贴 200 行。

## 7. 写作节奏(几条硬规则)

1. **先痛点后方案**。开篇 1~2 段必须建立共鸣(我也踩过这个坑 / 我也困惑过这个概念),再开讲。
2. **bug 类先抛结论**。`## 解决方法` 紧跟在 `## 问题描述` 后面,排查过程放更后面——读者急着要答案。
3. **每张截图前后都要有一句话过渡**,不要让图孤立。例:"端口号需要替换成你代理工具的实际端口号,可以在 windows 设置中找到:"  → 截图。
4. **不要写"综上所述"那种学术结尾**。结尾用"总结"(要点列表)或"拓展"(相关玩法、群友讨论)收尾,口语化。
5. **段落要短**。一段不超过 4~5 行,移动端阅读友好。
6. **避免空洞套话**。不要"本文将...首先...然后...最后"这种目录式开场,直接进入场景。

## 8. 语句通顺与语义连贯(基本功,写完必查)

这一节管的是"表达质量的下限"。去 AI 味管"不像 AI 写的",本节管"像人写且读得通"。**写完初稿,逐条过一遍,这是比风格更优先的底线:**

### 8.1 句子完整性

- 每句有完整主谓宾,不残缺、不杂糅。
- 读出来能一口气念完,断句处就是逗号/句号。
- 一句话只讲一个意思,塞不下的拆成两句。

### 8.2 指代清晰

- 每个"它 / 这 / 这个 / 那"在前一句都能找到明确所指。
- 指代模糊就重复名词,别怕重复(青花鱼不怕重复,AI 才怕)。

### 8.3 衔接连贯

- 相邻两句、两段之间要有逻辑关系(顺承 / 因果 / 转折),缺了就补连接词(然后、因为、但、说白了、所以说)。
- 每段第一句要能接住上一段结尾,接不上就在段首补过渡。
- 时间线、流程叙述必须按顺序走,跳步要说明。

### 8.4 段落单一职责

- 一段只讲一件事,讲完换段。
- 段落之间有递进或转折,不是并列堆砌。

### 8.5 朗读测试(最有效的自检)

- 全文默读一遍,卡壳、别扭、绕口的地方就是要改的地方。
- 长句拆短,短句砸重点,让节奏有起伏。

## 9. 去 AI 味(写完必过这道关)

> 融合 anti-vibe-writing / avoid-ai-writing-zh / zh-natural-writing 的方法论。青花鱼风格的底色是"老哥在工位上边操作边讲",而 AI 腔恰好是它的反面。**初稿写完,必须按下面五层过滤器 + 确定性 grep 过一遍**,把 AI 的痕迹全部揪出来。

### 9.1 第一层:词汇黑名单(见到就删或换)

这些词是 AI 味的指纹,正文里**能删就删,能换就换**:

| AI 味词 | 青花鱼式替代 |
|---|---|
| 赋能、打通(商业语境)、闭环、链路、底座、心智、生态、方法论、颗粒度、底层逻辑 | 大白话:让…能用、把…串起来、一套做法 |
| 值得注意的是、不难发现、众所周知、由此可见 | 直接说事,删掉 |
| 总而言之、综上所述、归根结底、说到底 | 删掉,或换成"说白了" |
| 本质上、核心是、至关重要、不可或缺 | 删掉,或换成具体描述 |
| 首先…其次…最后、其一…其二… | 删掉序号,直接并列 |
| 提升体验、降低门槛、打造闭环 | 改成具体行为:"把安装步骤从 10 步砍到 3 步" |
| 让我们、让我们一起 | 删掉,直接讲 |
| 在这…的时代、随着…的发展 | 删掉,直接进场景 |
| 研究表明、数据显示、专家指出(无来源) | 删掉,或换成"我实测" |

### 9.2 第二层:句式过滤(AI 最爱用的句式)

1. **"不是 X,而是 Y"**:一篇文章最多 1 次,超过就全删。AI 用它制造"深度思考"的假象,其实什么都没说。
2. **虚假让步三拍**(最隐蔽的中文 AI 模式):"虽然 A,但 B 也不差;更何况 C"——先抑后扬再转折。青花鱼式写法是直接给结论。
3. **排比式填充**:连续三句同构句("它不只是…更是…还是…")。偶尔用对仗可以,但绝不三连。
4. **报幕式过渡**:"让我们来看看""接下来,我们将探讨"。直接删。
5. **总结腔**:"通过本文,我们了解到…""总的来说,本文介绍了…"。青花鱼结尾是"总结"要点列表或"拓展",不写这种。
6. **自证式解释**:"我们之所以…是因为…"。AI 爱解释自己为什么这么写,人不会。
7. **模板化开头**:"在这个 XX 的时代""随着 XX 的快速发展"。青花鱼开头是"最近做 XX 需求时被折腾得够呛"这种具体场景。
8. **鸡汤/口号结尾**:"记住,真正重要的是…""希望你能…"。青花鱼结尾是干货或互动,不升华。
9. **旧❌新✅标准答案结构**:AI 爱写"以前是错的,现在这样才对"。避坑指南可以写,但不要每节都套这个模板。

### 9.3 第三层:格式过滤(格式也会暴露 AI 味)

1. **加粗过度**:AI 一段加粗 3+ 处。青花鱼规则:一段至多 1 处加粗,且只加粗结论句、关键词、数字。
2. **破折号过度**:`——` 一篇文章最多 2~3 次。AI 爱用破折号制造"思考感",人打字多用逗号、冒号、括号。
3. **每段一个小标题**:AI 爱给每段加 `###` 显得有条理。青花鱼规则:只给真正的步骤/章节加标题,过渡段不加。
4. **列表过多**:能用一句话说清的就别列表。3 项以内用顿号串在句子里,4 项以上才用列表。
5. **子标题对称**:AI 的标题爱搞对仗("优点与缺点""现状与展望")。青花鱼标题是口语化的。
6. **标题预告结论**:"深度解析 XXX 的底层逻辑"这种知识型标题。青花鱼标题是情绪钩子 + 数字。

### 9.4 第四层:节奏过滤(均匀感是 AI 的指纹)

1. **句长均匀**:AI 每句差不多长,读起来像节拍器。人写东西有长有短,短句砸结论,长句讲故事。
2. **段落长度均匀**:AI 每段都是 3~4 行。青花鱼规则:允许一段只有一句话,允许偶尔一段 6 行。
3. **同义词轮换**:AI 怕重复,一个意思换三个词说("使用/运用/借助")。人不怕重复,同一个词用到底反而自然。
4. **假口语混搭**:书面论证里突然蹦一句口语。青花鱼是全篇口语,不是局部口语。

### 9.5 第五层:内容过滤(虚胖是 AI 的通病)

1. **意义膨胀**:把小事说成大事("这一改动将深刻影响…")。删。
2. **新颖性膨胀**:"前所未有""开创新范式"。青花鱼说"真香""挺好使"。
3. **虚假全面性**:"从多个维度""不仅…而且…覆盖方方面面"。青花鱼只讲自己踩过的坑。
4. **虚假归因**:"研究表明""数据显示""专家指出"但没来源。删,或换成"我实测"。
5. **比喻密度过高**:同一段 2+ 个不同比喻。青花鱼一个段落一个比喻,讲透为止。
6. **缓冲词堆砌**:"其实""本质上""某种意义上"连续出现。保留一个口语化的"说白了"就够。

### 9.6 交付前最后一步:确定性 grep

用 grep 快速扫一遍残留的机器痕迹(代码块内的不算):

```bash
grep -n "——" 文章.md          # 破折号,超过 3 次就处理
grep -n "…" 文章.md            # 省略号字符,非口语场景删
grep -nE "→|•" 文章.md         # 正文里游离的箭头/圆点
grep -niE "\[cite|oaicite|contentReference" 文章.md   # 模型残留标记,必删
```

> 中文全角引号 `“ ”` 是青花鱼正常使用的,**不要**误删。去 AI 味不是躲检测器,是让文字真的像人打的。

## 10. 写作前自检清单

新文章交付前,逐项对照:

- [ ] title 有情绪钩子 / 数字承诺,不是平铺直叙?
- [ ] 开头 1~2 段讲了痛点或个人经历,不是干巴巴的背景?
- [ ] 复杂概念都配了生活化类比?
- [ ] 二级标题按"背景 → 步骤 → 避坑 → 总结"组织?(教程类)

## 11. 起草新文章时的推荐流程

1. 先问清楚作者(用户):这是什么类型?教程 / bug / 科普 / 实战?核心要传达什么?
2. 按第 3 节选模板,搭骨架。
3. 按 4~7 节填肉:类比、emoji、加粗、配图占位、口头禅点缀。
4. 按第 8 节过一遍"语句通顺与语义连贯"。
5. 按第 9 节过一遍"去 AI 味"过滤器。
6. 用第 10 节清单自检(含语句通顺、去 AI 味条目)。
7. 输出到 `source/_posts/NN-标题.md`(创建方式见 `AGENTS.md`),cover 留给作者。
