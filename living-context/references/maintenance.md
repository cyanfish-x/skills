# 整理与重建

用于建立知识入口、合并、迁移或退出知识。范围来自用户请求及本次实际变更；全库审计应是明确的独立任务。

## 主动识别重建机会

用户要求评估、整理已有知识或建立知识入口时，在本次范围内同时评估内容价值与组织方式，不以“已有目录可用”直接结束判断。日常开发只根据已触及的材料识别机会，不为提出建议另做全库巡检。

出现以下具体问题时，判断迁移或重组是否比补充索引更有收益：当前规范与历史方案混放、同一主题散落且重复维护、目录名无法提示知识用途，或未来任务需要跨多篇历史记录拼接当前状态。建议应引用实际文件或章节说明问题，不能仅因目录不叫 `docs/` 或未采用六类名称就认定需要重建。

有明确收益时，主动给出可审查的重建方案，而不是只问“要不要重建”。方案至少交代：

- 当前结构造成的具体检索或维护问题，以及局部整理为什么不足。
- 目标目录树和“原文件或章节 → 目标位置 → 移动、改名、拆分、合并、保留或删除”的映射。分清重组已有知识与需要另行核验或补写的内容。
- 哪些理由、证据和历史路标保留，哪些入口、相对链接、锚点或工具依赖路径需要同步更新；未核查范围明确标注。
- 迁移范围、主要风险与验收方式，随后请求用户确认该具体方案。

目标结构可采用 `docs/index.md` 作为路由，按已有内容选择 `intent/`、`spec/`、`architecture/`、`decisions/`、`engineering/`、`research/`。也可沿用现有根目录或用主题文件加章节组织。给出明确推荐，不机械生成空目录；重建应让当前知识更容易找到，不能只换文件夹名称。

例如，已确认一份旧方案同时承载当前 API 行为、选型理由和过期步骤时，可建议分别归入规范和决策记录，并按剩余价值处理旧步骤。映射必须来自实际阅读，不根据“方案”二字直接拆分或删除。

## 授权后执行重建

提出方案前完成必要的只读调查与映射准备。用户仅要求“评估文档”“整理知识”或“无价值可删除”，不等于授权成批迁移、目录改名或整体重建；这些结构变更应等用户确认具体方案。说明确认用于确定迁移范围，不影响已经授权的局部维护。等待时继续可独立完成的工作，避免先做与待确认迁移互相抵消的改动。

用户已明确批准该方案及范围时，直接执行，不重复确认。迁移授权不自动改变产品要求，也不自动覆盖修改宿主配置或项目规则文件；需要这些动作时将其列入方案范围。

按批准的映射迁移、合并和改名，保留知识的条件、来源、不确定性与独有理由，同步入口及受影响引用。目标位置出现冲突时检查并合并，不覆盖未知内容。删除候选仍需遵守下文的退出规则。完成后核对原有高价值内容是否可定位、当前入口是否直达新状态，以及受影响路径和锚点是否有效。

用户拒绝或暂缓后继续采用现有结构，在没有新证据或用户重新提出需求时，不反复推销同一重建。无需重建也是有效结论：用户正在评估整体知识时简述理由；普通开发任务不增加固定汇报。

## 建立或调整入口

先检查允许范围内已有文档入口、主题与引用。复用能承载任务路由的位置；同名目录或索引用途不同，不覆盖或强制迁移。确需新增入口时，从已有的有价值记录构建，避免生成空分类或推测出来的项目规范。

请求只是初始化知识结构时，建立足够开始工作的最小入口；不要顺带从整库代码反推产品意图。当前实现观察可以标为观察，不能代替用户确认的要求。接入宿主或修改项目规则文件是单独的集成动作，仅在请求覆盖时进行。

## 按陈述处理退出

先读候选内容与它的相关入链，核对是否仍有不可替代的理由、证据、契约或保留要求。分类依据是剩余价值，不是文件年龄或上次访问日期。

| 内容状态 | 合适动作 |
| --- | --- |
| 重复，但仍含独有理由或证据 | 先并入维护位置，继承条件与不确定性，再改引用 |
| 当前已失效且会误导 | 标明失效或替代状态，从当前有效路由退出 |
| 当前不适用，但复发代价高 | 保留简短失败原因、适用条件及历史或证据指针，按需发现 |
| 必须保留的审计或契约记录 | 保留原记录，另设当前摘要或明确替代关系 |
| 已无剩余价值且无保留义务 | 在授权范围内删除，处理受影响链接 |
| 无法判断或来源不可恢复 | 暂保留并说明未知，不把不确定性当成删除依据 |

退出默认上下文不等于物理删除。不要因为“Git 会保存”就删掉未受版本控制的唯一证据；若依靠历史恢复，应核实内容确已保存在可定位的提交中，并为高价值理由保留具体路标。无法证明可恢复时，优先保留或明确归档。

移动或删除前，检查允许范围内指向候选路径或锚点的引用；同步改为新位置、替代摘要，或删除无用路由。无法访问的外部入链只能声明未核查，不能宣称所有引用已修复。

## 验证与报告

检查保留下来的结论是否仍带有原始条件、来源和未知项；当前入口是否直接表达当前状态；修改过的链接是否到达正确文件或章节。已有保留规则时检查迁移是否遵守。

报告具体新增、修订、合并或退出了什么以及理由。保留未解决冲突，区别“退出默认路由”“归档”“删除”。局部整理不能据此宣称全库已无漂移。
